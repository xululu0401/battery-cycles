# 一块电池还能撑几年（battery-cycles）

填一次系统里的电池健康度，算出照现在的用法还能撑几年跌到 80%；以及把每次充电跨过的那段电量挪到电池中段，能把这笔时间拿回多少。

- **实测速率**：健康度 ÷ 已经用了多久 = 年化衰减（点/年）。一个读数定不出「循环 vs 放着老化」的拆分，所以给两侧而不是一个假装精确的数。
- **应力权重**：20%–80% 最轻（0.25），贴着 0% / 100% 两端最贵（1.30 / 1.00）。为什么 0% 比 100% 更贵是设计选择，不是实测常数。
- **按放出去的电量加权**，不按充电次数加权：一天放掉同样多的电，充 1 次和充 2 次结果相同（否则会出现「少充几次就更耐用」这种同义反复）。
- **窗口由用量决定**：一次充电跨过多宽 = 日耗电 ÷ 每天充电次数，不由充电器决定。
- **四种充法并排**：现在这样 / 挪进中段 / 充勤一点 / 一口气放到 0%——每张牌都标出年损耗单元、年化衰减、到 80% 的年数与相对第一行的月数。
- **35 项结构自检**：区间应力权重与解析积分对拍、权重在自由区两端连续、单点权重「0% > 100% > 50%」、同样宽度越靠中段越省、同样居中越窄越省、一次跨过宽度 = 日耗电 ÷ 次数、实测年化 = 点数 ÷ 年数、乐观不低于悲观、已到阈值不给日期、日耗电 >100% 封顶……
- **四种导出**：时间线 CSV / 说明 Markdown / 结果卡 PNG（1080×1350）/ JSON 备份（可再导入）；改一个数字立刻重算；存本机、刷新恢复。

**不做什么**：不联网、不查行情、不内置任何品牌参数或循环次数；不判断电池是不是已经坏了（鼓包、突然掉电、虚电）；
不含车载动力电池；不预测个别电芯的质量问题；不给「该不该换机」的消费建议；不做单位换算与充电时间估算。

数字全部由使用者填写。默认数据、内置场景、封面与结果卡里的数字都是**虚构示例**。

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 构建产物（单文件，可直接打开） |
| `template.html` / `core.js` / `ui.js` | 源码；`build.cjs` 把后两者内联进 `index.html` |
| `tests/core.test.cjs` | 核心测试：`node --test tests/core.test.cjs` |
| `cover.png` | 封面 1200×1200 |
| `验收脚本.cjs` | 浏览器验收（真实 DOM 事件、四种下载落盘、窄屏与长文本实测） |
| `说明数字校验.cjs` | 把发布说明里每个数字回溯到同一次引擎输出 |

## 本地运行

```bash
node build.cjs                  # 生成 index.html
node --test tests/core.test.cjs # 48 项核心测试
node 说明数字校验.cjs            # 校验发布说明里的数字
python3 -m http.server 8917     # 然后打开 http://127.0.0.1:8917/index.html
```
